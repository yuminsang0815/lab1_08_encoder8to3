# 실험 전 레포트: 8:3 인코더

작성일 2026-09-19.

## 목적과 예상값

8비트 원-핫 입력 `i[7:0]` 중 1이 위치한 자리를 3비트 2진 코드 `a[2:0]`로 변환합니다. top은 `encoder8x3`입니다. 비우선순위 인코더이므로 1이 없거나(`8'h00`) 2개 이상 활성화된 다중 입력(Multi-hot) 조건에서는 default 분기를 통해 `3'b000`을 반환합니다.

| i[7:0] (hex) | 활성 비트 | a[2:0] (2진) | a (10진) | 비고 |
|---|---|---|---:|---|
| 8'h80 | i[7] 단독 활성 | 000 | 0 | 정상 원-핫 변환 |
| 8'h01 | i[0] 단독 활성 | 111 | 7 | 정상 원-핫 변환 |
| 8'h00 | 무입력 | 000 | 0 | 예외 처리 (default) |
| 8'h03 | i[1], i[0] 다중 입력 | 000 | 0 | 예외 처리 (default) |

## 환경과 입력 파일

Windows, Git 2.55.0, VS Code 1.136.1, XSim 2026.1을 사용했습니다. 공개 템플릿의 커밋 `740aef5`를 공백이 있는 별도 폴더에 새로 clone했습니다. `LAB1.code-workspace`는 `vivado_2026_1/08_encoder8to3`를 PROJECT, `common`을 COMMON으로 연결합니다.

[RTL](../../src/encoder8x3.v), [TB](../../sim/tb_encoder8x3.sv), [XDC](../../constraints/encoder8x3.xdc)를 사용했습니다. TB top은 `tb_encoder8x3`이며 0부터 255까지 256가지 전수 입력을 10ns 간격으로 인가합니다. 원-핫 판정 기대 모델과 비교하여 256건 완료 시 PASS를 출력하고 2560ns에 종료합니다.

## 실행과 관찰

VS Code 새 창에서 workspace를 열고 slang-server와 VaporView를 활성화했습니다. 저장 후 Terminal → Run Task...의 Check tools, Simulate를 실행하고 Open waveform으로 VCD를 열었습니다. `i,a`를 추가하고 Zoom to Fit와 ns 단위를 선택했습니다.

실제 [VS Code 작업 실행 로그](../../evidence/08/vscode/simulation.txt)에서 `LAB1_PASS encoder8x3 cases=256`과 2560ns 종료를 확인했습니다.

| 구간(ns) | i[7:0] (hex) | a[2:0] | 해석 |
|---|---|---|---|
| 0–10 | 00 | 000 (0) | 무입력: default 분기에 의해 0 출력 |
| 10–20 | 01 | 111 (7) | i[0] 활성화 정상 인코딩 |
| 30–40 | 03 | 000 (0) | 다중 입력 발생: 예외 처리로 0 출력 |
| 1280–1290 | 80 | 000 (0) | i[7] 활성화 정상 인코딩 |

전환 순간 대신 구간 중간에서 커서를 읽었습니다. 파형만 눈으로 맞아 보이는 것에 더해 자동 비교 256건과 정상 종료를 함께 확인했습니다.

## 보드 실험 계획

KEY1\~8(i[7:0]), LED1\~3(a[2:0]), LVCMOS33입니다. Vivado에서 같은 TB를 실행한 다음 bit를 생성하고 보드에 다운로드합니다. KEY8 단독 누름 시 7(111)로 LED 3개가 모두 켜지는지 확인하고, 버튼 2개를 동시에 눌렀을 때 우선순위 없이 모든 LED가 꺼지는 default 처리 동작을 사진·영상에 담을 계획입니다.
